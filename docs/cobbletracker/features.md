# Features
CobbleTracker implements several features to assist players in finding and tracking rare Pokémon spawns across the server.

*   **Radar HUD**: The client-side HUD points players towards tracked Pokémon. Technically, it uses an `ArrowHudRenderer` coupled with a `HuntScanner` that processes hunted targets, offering a visual arrow and distance indication.
*   **Minimap Waypoints**: Integrated with popular minimap mods (Xaero's, VoxelMap, and JourneyMap). Using `MinimapWaypoints` and configuration through `MinimapSettings`, clicking on coordinates in a spawn announcement drop a temporary waypoint on the player's minimap so they can easily navigate to the location.
*   **Spawn Beam**: Spawns a highly visible vertical light beam at the exact location of a tracked spawn to make spotting it easier. Managed by `BeamRenderer` and configured in `BeamSettings`, it can inherit colors from the tracker category, last for a specific duration, and render at a customizable height and radius.
*   **Legendaries Spawner**: A built-in, context-aware spawning engine (`LegendaryDirector`). Under `mode: auto`, it caches and scans the live Cobblemon spawn pool to detect if label-based tiers (like "legendary", "mythical", or "ultra_beast") are natively covered. If a tier lacks datapack coverage, CobbleTracker steps in and spawns them. It parses rules to ensure proper environment fit (biome tags, time, weather, height limitations) before selecting a species, ensuring Pokémon don't spawn out of their element.
*   **Discord Webhooks**: A highly performant webhook integration that offloads network requests from the main server thread. Handled in `DiscordWebhook`, it uses the native JDK `HttpClient` and a bounded queue (`ArrayBlockingQueue`) handled by a daemon thread. This prevents game freezes on network timeouts. It drops old queue entries if it falls behind to prevent memory exhaustion, and supports customizable JSON template payloads (`DiscordMessage.render`).
